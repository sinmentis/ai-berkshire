# Agent-Neutral Skill Sources (Copilot CLI Compatibility) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite all 19 `skills/*.md` canonical source files so their procedural/orchestration text uses agent-neutral action language instead of Claude-Code-specific tool names, regenerate `codex-skills/*/SKILL.md` from the updated source, and add Copilot-CLI-specific operating documentation — so the skill set works correctly (not just "installs") under GitHub Copilot CLI, while remaining fully functional for Claude Code and Codex. (`codex-skills/` has a 20th, hand-written Codex-only package, `investment-memo-craft`, with no `skills/*.md` source — out of scope here.)

**Architecture:** One canonical source (`skills/*.md`), one generated package tree (`codex-skills/*/SKILL.md`, regenerated by the existing `scripts/sync-codex-skills.py`), plus a new `COPILOT.md` sibling to `CLAUDE.md`/`AGENTS.md`. No new directories, no new sync scripts, no change to `tools/*.py`.

**Tech Stack:** Markdown source files, existing Python sync script (`scripts/sync-codex-skills.py`), `git`, `grep`.

Spec: `docs/superpowers/specs/2026-07-06-copilot-cli-skill-compatibility-design.md`

## Global Constraints

- Only orchestration/tool-naming language changes. Domain content (four-masters methodology, checklists, scoring rubrics, report structures, `tools/*.py` invocation examples) stays byte-for-byte identical.
- All prose stays in its original language (Chinese for `skills/*.md` bodies; the small English scaffolding this plan adds to `COPILOT.md`/`AGENTS.md` follows those files' existing language).
- Never leave any of these Claude-Code-specific terms in `skills/*.md` after editing: `TeamCreate`, `TaskCreate`, `TaskUpdate`, `SendMessage`, `TeamDelete`, `shutdown_request`, `WebSearch`, `WebFetch`, `Bash`（作为工具名连用，如"使用Bash调用"）, `Task 工具` / `Task工具`, `Agent 工具` / `Agent工具`, `subagent_type`, `run_in_background`, `team_name`（作为字段名）, `agent_type`（作为字段名）.
- Every task's acceptance check is a `grep -n` for the banned-terms pattern below, expecting **no output** (exit code 1) for the file(s) that task touches:
  ```bash
  grep -nE "TeamCreate|TaskCreate|TaskUpdate|SendMessage|TeamDelete|shutdown_request|WebSearch|WebFetch|Task ?工具|Agent ?工具|subagent_type|run_in_background|team_name|agent_type" <file>
  ```
- Work happens on branch `copilot-cli-support` in `~/work/ai-berkshire` (already checked out). Before every commit in this plan, run `git branch --show-current` and confirm it prints `copilot-cli-support` — this environment has shown it can silently switch branches; do not trust the prior state.

```markdown
# AI Berkshire — GitHub Copilot CLI Guide

This repository's `skills/*.md` files are agent-neutral: they describe
research workflows in terms of actions (search the web, launch a background
sub-task, read/write a file) rather than any single coding agent's specific
tool names. This file maps those actions to GitHub Copilot CLI's actual
tools, alongside `CLAUDE.md` (Claude Code) and `AGENTS.md` (Codex).

## Tool mapping

| Skill text says | Use in Copilot CLI |
|---|---|
| "启动后台子任务" / "并行启动 N 个子任务" (launch a background sub-task / launch N in parallel) | The `task` tool. For true parallelism, issue all N calls in the **same response** — one tool call per response runs sequentially. |
| "联网搜索" (search the web) | The `web_search` tool for a synthesized answer, or `web_fetch` to read a specific URL. |
| "通过命令行调用工具" / `python3 tools/...` (run a command-line tool) | The `bash` tool. |
| "读取/写入文件" (read/write a file) | The `view` tool to read, `edit` to modify, `create` for new files. |

No specific model name is pinned here — model selection for sub-tasks is
left to the user's or agent's own configuration, not hardcoded into this
shared repo file.

## Date discipline

Before starting any research, run `date` via the `bash` tool to confirm
today's actual date. Treat that date as the baseline for "latest" data
(prices, market cap, most recent filings) and state the data-cutoff date in
the report header. Never assume the current date from training data — this
is the single most common failure mode observed when running these skills:
training data goes stale and a model will confidently cite outdated market
levels, rates, or index values unless it is explicitly forced to verify
against a live search first.

## Checkout path discipline

Resolve the actual local repository checkout path before calling
`tools/*.py` — do not assume a fixed home-directory path like `~/ai-berkshire/`.
If a session starts outside the repo, locate the real checkout first
(e.g. `find ~ -maxdepth 3 -iname ai-berkshire -type d`).

## Everything else

The "Research Quality Rules" and "Editing Rules" in `AGENTS.md` are already
platform-agnostic and apply as-is to Copilot CLI sessions.
```
